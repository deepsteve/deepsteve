Welcome to Deep Steve

You didn’t open this tab — an agent did. It is running in the tab next to this one. It read one instruction, called one tool, and painted this page into a tab of its own. That is the whole product, and you just watched it happen.

What you are looking at

A display tab

A page an agent opens beside your terminals. It behaves like any other tab — closeable, renameable, grouped with the project it came from — but it is one-shot: it lives for the session and closing it destroys the page.

Ask any agent for a chart, a dashboard or a report and it can hand you one of these instead of printing text at you. For a page a project should keep, there are project mods further down.

The window around you

Tabs are sessions

Every tab in the strip is a real terminal running a real agent, with its own conversation. They survive a page reload, a daemon restart and closing the browser — the agent lives in a tmux pane, not in this page.

Projects ⌘P

The rail on the left groups your tabs by the folders they are working in. A project is a name plus a list of folders; a tab joins it when its working directory sits inside one of them.

“+ New project” at the bottom of the rail registers one. ⌘↑ / ⌘↓ cycle between them.

Mods — how Deep Steve grows

The Mods modal

Open it from the grid button in the tab strip, or type #mods at the start of an empty composer line. Everything installed is listed in one place, grouped by what it is: Apps, Panels, Fullscreen, Games, Tabs, Background, Skills, and Available (things you could install but haven’t).

Enabling and disabling a mod is per browser, stored locally — it never reaches the server. Two browsers on the same machine can run different sets.

Apps

A mod that is a place you work from rather than a tool you visit. Apps get their own section at the top of the projects rail, an entry in the command palette, and quiet mode (⌘\) which takes the surrounding chrome away and leaves the app alone on screen.

Shipped today: Workshop, Timecard and Simeon.

Project mods

The durable sibling of a display tab: a page an agent writes for one project, stored in the repo at .deepsteve/mods/<name>/ and meant to be committed — so it survives a re-clone and reaches everyone else working on the project.

They are found by scanning the repos of your registered projects, so a repo has to belong to a project first.

Work that happens without you

Scheduled tasks

Local cron for agents. The Scheduled panel docks on the right; + New takes a prompt, a project and a schedule. A run is an ordinary local session, so it keeps that project’s tools and MCP servers — which is the point, and what a cloud runner cannot do.

Fires open in the background, report themselves finished, and tidy up their own tab.

Issue sessions

The bolt button in the tab strip picks an issue from your tracker, creates a worktree for it, and starts an agent already primed with the issue text. If a worktree for that issue already exists it resumes it and says what was already there — nothing is ever reset.

Skills

Reusable workflows, off by default

Skills are canned procedures your agents can invoke by name — /deepsteve:display-tab, /deepsteve:fork, /deepsteve:merge and others. In Codex sessions the same skill is $deepsteve-display-tab.

They start disabled. Turn the ones you want on in the Skills section of the Mods modal; enabling one installs it for your agents on the spot.
